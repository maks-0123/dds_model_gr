# Тесты нелинейности ЦАП (AD9081): SFDR / HD2 / HD3 / IMD3

Цепочка: `dds_gr_all.v` → Verilator (shared lib) → GNU Radio (`dds.grc`, File Sink) → `sfdr.py` / `dds_measure` (Rust).
Каждая точка дополнительно считается побитовой Python-моделью `model_ref.py`. Измерение должно совпасть с ней с точностью ~0 дБ: это проверка всей цепочки.

## Файлы

| файл           | что делает                                                                                                            |
| -------------- | --------------------------------------------------------------------------------------------------------------------- |
| `dds_gr_all.v` | DDS (1 или 2 тона) + статическая модель ЦАП: INL «дуга» (HD2), INL «S» (HD3), рассогласование унарных сегментов (DNL) |
| `build.sh`     | сборка → GNU Radio → измерение → эталон → отчёт, по всем сценариям и точкам Table 16                                  |
| `sfdr.py`      | когерентное измерение: SFDR, HD2, HD3 (однотон) и IMD3 (двухтон), запись в CSV                                        |
| `model_ref.py` | побитовая копия Verilog на Python: ожидаемые метрики, реальные INL/DNL модели, график INL/DNL                         |
| `report.py`    | `results/summary.md` + графики SFDR(fOUT), IMD3(fOUT) в сравнении с Table 16                                          |
| `measure_rs/`  | тот же измеритель на Rust (`cargo run --release -- --file x.bin --m 2457 [--m2 2459]`)                                |

## Запуск

```bash
cd scripts
./build.sh                                  # все сценарии, все точки (~66 сборок)
QUICK=1 ONLY="inl3 full" ./build.sh         # быстро: 3 частоты + 1 двухтон, два сценария
SRC=~/gnu-dds-all-v GRC=~/gnu-dds-all-v/dds.grc RAW=~/gnu-dds-all-v/scripts/out.bin ./build.sh
```

Путь `RAW` должен совпадать с путём в блоке File Sink в `dds.grc`. Тип элемента sink — `int` (int32).

## Что изменилось относительно старой версии и почему

1. **AW = 16 (≥ LOG2N = 15).** При AW = 14 усечение фазы даёт спуры около −80 dBc. Они маскировали нелинейность и случайно оказывались рядом с 77–80 dBc из даташита. Сценарий `aw14` оставлен как демонстрация этого эффекта.
2. **INL раскладывается на чётную и нечётную части.** Чётная часть — «дуга» C2·(1−x²), даёт HD2. Нечётная — «S-кривая» C3·2.598·(x³−x), даёт HD3. Линейная часть вычтена, поэтому нет ошибки усиления и насыщения у края шкалы. В старой модели было только `8·x³`: HD2 отсутствовал, реальный INL был около 3 LSB, а у края шкалы коды насыщались.
3. **DNL моделируется рассогласованием 64 унарных сегментов** (current-steering ЦАП). Старый треугольник с периодом 97 на деле давал DNL около ±1 LSB, плюс разрыв в нуле из-за беззнакового `code`. Теперь DNL = ±3.5 LSB, а случайное блуждание ошибок сегментов само создаёт INL.
4. **Сценарий `full`** (SEED=8, INL2 = INL3 = 3 LSB, DNL 3.5 LSB) даёт INL от −7.9 до +5.2 LSB и DNL от −3.5 до +3.1 LSB. Это значения из Table 3.
5. **Выход с FRAC = 4 дробными битами** (полная шкала 2^19). Дробные ошибки INL/DNL не перекругляются в 1 LSB.
6. **Двухтон.** Две DDS суммируются до округления. Уровень −6 dBFS на тон, M2 = M1 + 2 (разнос 0.73 МГц при 12 GSPS; в Table 16 — 1 МГц). Старый двухтон в режиме `TEST_MODE=1` проходил мимо `dac_nonlin`.
7. **Частоты как в Table 16:** fOUT = M/32768·12 ГГц, M — ближайшее нечётное.

   | fOUT, МГц | 70  | 100 | 500  | 900  | 1900 | 2600 | 3700  | 4500  |
   | --------- | --- | --- | ---- | ---- | ---- | ---- | ----- | ----- |
   | M         | 191 | 273 | 1365 | 2457 | 5189 | 7099 | 10103 | 12289 |

8. **Измерение только когерентное**, прямоугольное окно, с проверкой утечки. Тип данных int32 и SKIP одинаковые в Python и Rust.

## Параметры Verilog (`-G...`)

`SRC` (0 — DDS, 1 — io_in), `TONES` (1/2), `NONLIN` (0/1), `M_CYCLES`, `M_SPACING`, `M_FROM_IO`, `AW`, `DW`, `RW`, `FRAC`, `LOG2N`, `AM_1T` (29274 = −7 dBFS), `AM_2T` (32768 = −6 dBFS на тон), `INL2_Q`, `INL3_Q`, `DNL_Q` (в 1/16 LSB), `SEG_BITS`, `SEED`, `OUT_SEL`.
Порты верхнего модуля не изменились: `clock, reset, io_in[31:0], io_out[31:0]`. Старого `TEST_MODE` больше нет.
